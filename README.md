# MC Mod Builder

Android-приложение, которое **само мод не компилирует** (это невозможно сделать
на телефоне — нужен Gradle + JDK + гигабайты зависимостей Fabric/Forge). Вместо
этого оно:

1. Загружает выбранный ZIP-архив проекта мода в ваш GitHub-репозиторий.
2. Запускает там workflow `build-mod.yml`, который клонирует нужный шаблон
   (Fabric / Forge / NeoForge), накладывает поверх ваши файлы и собирает `.jar`
   через `./gradlew build`.
3. Опрашивает статус сборки и, когда она завершена, скачивает готовый `.jar`
   из GitHub Release и сохраняет на телефон.

## Шаг 1. Соберите само приложение через GitHub Actions

Как и с Screen Hold AI — вы не компилируете APK на телефоне, а отдаёте это
GitHub:

1. Создайте новый репозиторий на GitHub (например `mc-mod-builder`).
2. Залейте туда содержимое этого архива целиком (через приложение GitHub,
   Working Copy или веб-интерфейс "Add file → Upload files").
3. Откройте вкладку **Actions** в репозитории — workflow `Build app APK`
   запустится автоматически при пуше в `main`.
4. Когда сборка завершится, зайдите в неё и скачайте артефакт
   `mc-mod-builder-debug-apk` — это и есть `app-debug.apk`.
5. Установите APK на телефон (разрешите установку из неизвестных источников).

## Шаг 2. Создайте Personal Access Token

Приложению нужен токен, чтобы от вашего имени заливать файлы и запускать
workflow в репозитории:

1. GitHub → Settings → Developer settings → **Personal access tokens →
   Fine-grained tokens** → Generate new token.
2. Repository access: выберите этот же репозиторий.
3. Permissions: **Contents — Read and write**, **Actions — Read and write**.
4. Скопируйте токен (он показывается один раз).

## Шаг 3. Настройте приложение

Откройте приложение на телефоне → разверните "Настройка GitHub" → впишите:
- Владелец репозитория (ваш username или организация)
- Название репозитория
- Personal Access Token

Нажмите "Сохранить" — данные останутся в приложении между запусками.

## Шаг 4. Соберите мод

1. Выберите ZIP-архив проекта мода (исходники, `src/main/...`,
   `fabric.mod.json` / `mods.toml` и т.п. — как обычно у вас в проекте).
2. Выберите загрузчик: `fabric`, `forge` или `neoforge`.
3. Укажите версию Minecraft.
4. Нажмите "Собрать мод" — приложение покажет статус и через несколько минут
   предложит сохранить готовый `.jar`.

## Важные ограничения (честно, чтобы не было сюрпризов)

- **Шаблоны загрузчиков.** Workflow клонирует официальные шаблоны
  (`FabricMC/fabric-example-mod`, `MinecraftForge/MDK`, `neoforged/MDK`) и
  пытается найти ветку под вашу версию Minecraft. Не для каждой версии есть
  точная ветка — иногда workflow возьмёт ближайшую/основную ветку, и тогда
  может понадобиться вручную поправить `gradle.properties` в вашем ZIP
  (mappings, версии Forge/NeoForge и т.п.), если сборка упадёт с ошибкой
  версий.
- **Первая сборка Forge/NeoForge долгая** (Gradle скачивает и деобфусцирует
  Minecraft) — до 10–15 минут. Таймаут в приложении — 15 минут.
- **Структура ZIP.** Проще всего, если в архиве уже лежит нужная структура
  Gradle-проекта мода (как её создаёт официальный шаблон). Приложение
  накладывает содержимое вашего ZIP поверх шаблона — файлы с теми же именами
  (например, ваш `build.gradle`) перезапишут файлы шаблона.
- Логи каждой сборки всегда можно посмотреть во вкладке **Actions** репозитория,
  если что-то пошло не так.

## Структура репозитория

```
app/                          — исходники самого Android-приложения (Kotlin/Compose)
.github/workflows/
  android-build.yml           — собирает APK самого приложения
  build-mod.yml                — собирает мод (fabric/forge/neoforge) по запросу из приложения
```
